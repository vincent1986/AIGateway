# AIGateway V2 全新产品需求文档 (PRD)

## 1. 文档概述

### 1.1 项目背景与核心演进

AIGateway 是一款聚焦于“省 Token、多工具、轻量化”的本地 AI 流量底座与反向代理网关。
在 V2 版本中，系统架构完成降维打击式的演化：**由 V1 传统的“死板改写下游工具物理配置”模式，全面升级为“一次覆盖、终身接管、内存动态虚拟路由”的本地微型网关模式。**

通过流量拦截，避开环境变量冲突；通过引入 **SQLite 本地数据库**，承载高频流式传输（SSE）下的 Token 统计与计费，为多厂家同名模型的智能故障转移（Failover）提供绝对稳定的底层支持。

### 1.2 核心改进指标

1. **流量接管胜过物理修改**：一次性将下游工具（ChatGPT, openClaw 等）的 `base_url` 指向本网关，后续切换通道完全在网关内存中热调度，**实现免重启终端的丝滑热切换**。
2. **职责彻底解耦**：厂家管理只管通路与协议；应用管理只负责卡片式工具接入；模型管理承担多渠道横向聚合、额度追踪与核心调度。
3. **数据架构升级**：引入 SQLite 本地轻量级数据库，彻底废弃高频读写易损坏的纯 JSON 存储。
4. **流式毫秒级熔断（Circuit Breaker）**：精准拦截流式传输（SSE）状态，捕获上游 429（限流）或额度耗尽报错，300ms 内无感降级重试至备用渠道。
5. **生态平滑扩展**：无缝兼容 ChatGPT (原 Codex)、Claude Code、openClaw、harness 等主流工具。

## 3. 核心功能模块详细需求

### 3.1 导航与全局 UI 交付规范 (需求 1, 5, 8)

* **菜单架构调整**：
* `[厂家管理]`（原厂家模型模块瘦身版）
* `[模型管理]`（**V2 全新引入**，聚合调度看板）
* `[应用管理]`（原配置文件管理，升级为卡片式工具市场）
* `[统一入口]`（网关核心状态、监听配置与运行日志）
* `[Token 统计]`（多维度用量分析看板）


* **UI 视觉与语义锁死规范 (避免 AI 自由发挥)**：
* **色系约束**：全站强制采用暗黑科技风色系。
* **状态标签 (Tag) 规范**：
* `🟢 正常运行 / 已接管 (Success)`：通路畅通、代理运行中。
* `🟡 备用渠道 / 待激活 (Warning)`：配置成功但处于低优先级队列，或配置修改未保存。
* `🔴 额度耗尽 / 熔断异常 (Destructive)`：Token 归零、触发上游限流或连接超时。
* `⚪ 已停用 / 未配置 (Muted)`：移出调度队列或未启用。





### 3.2 厂家管理模块 (Provider Management) (需求 2, 4, 6)

* **职责边界**：只管理厂家的底层物理连接通路（API Key / Base URL）以及通道全局开关。
* **功能需求**：
1. **内置厂家预设库（Presets）**：禁止让用户纯手动填写繁琐的参数。内置常用厂家（DeepSeek 官方、硅基流动、Ollama、OpenAI、通义千问等）的默认 Base URL 和接口特征，用户点选后仅需输入 API Key 即可快速导入。
2. **数据格式标准切换（需求 4）**：在单厂家配置中增加 **【数据格式标准】** 切换单选框：
* `标准 OpenAI 格式 (Standard OpenAI)`：网关中间件强制规整该厂家的上下行报文（如抹平 Ollama 非标端点或特定厂家的特殊字段差异）。
* `原样转发 (Passthrough)`：网关直接透传请求和响应 `body`，不做任何协议解析。


3. **模型列表瘦身（需求 6）**：下方的模型列表移除一键写入工具等繁琐操作。单行仅保留 **【启用/停用开关 (Toggle)】** 和 **【移除模型 (Remove)】**。



### 3.3 模型管理模块 (Model Management) —— V2 核心核心 (需求 3, 7)

* **职责边界**：横向聚合不同厂家提供的同名模型（例如将“DeepSeek 官方”和“硅基流动”提供的 `deepseek-v4-pro` 聚合为一个虚拟模型组），执行多渠道调度。
* **功能需求**：
1. **横向聚合看板（需求 3）**：以“通用模型名称”为主键行（Row），支持展开。展开后以表格展示该模型组下绑定的所有厂家供应详情：
| 模型组名称 | 供应厂家 | 当前状态 | 已用量 (Token) | 剩余额度/套餐包 | 已应用工具 |
| --- | --- | --- | --- | --- | --- |
| **deepseek-v4-pro** | DeepSeek (官方) | 🟢 正常(主) | 368,619 | ￥50.00 | ChatGPT, openClaw |
| *(展开子行)* | 硅基流动 | 🟡 备用 | 0 | $10.00 | ChatGPT, openClaw |


2. **流式熔断与智能故障转移策略（Failover）（需求 7）**：
* **拖拽优先级队列**：用户在 UI 上可自由调整一个模型组内不同厂家的调用顺序（优先级队列）。
* **自动切换触发器**：网关在转发时，一旦捕获到当前主力厂家返回 `429 (Rate Limit)`、`401 (账户异常)` 或 `额度耗尽` 报错，**必须在 300ms 内对客户端保持断流，并在后台自动将请求重试并滑向下一顺位厂家通道**。
* **自动停用**：当队列内所有备份厂家全部耗尽，触发最终保护，自动停用该模型组，并向客户端返回标准 OpenAI 格式的错误响应（避免下游客户端崩溃闪退）。





### 3.4 应用管理模块 (Application Management) (需求 1, 2, 5)

* **职责边界**：只负责下游 AI 编码/自动化工具（ChatGPT、Claude Code、openClaw、harness 等）的物理配置文件定位、快照备份与一键覆盖接管。
* **功能需求**：
1. **更名落地（需求 5）**：全局全局替换，将原 `Codex` 文案、前后台组件及变量全面重构更名为 **`ChatGPT`**。
2. **工具市场（Grid Layout）网格视图**：
* 彻底废弃原两栏平铺布局。升级为标准的**响应式网格卡片流**，卡片样式高度统一，支持未来无限扩展新工具。
* **卡片标准标准元素**：工具 Logo + 工具名称 + 物理路径输入框 + 状态标签 + 快捷操作组（自动检索、手动选择、一键回滚）+ **【一键接管/覆盖】** 主动作按钮。


3. **控制解耦与接管机制（需求 1, 2）**：
* **移除**页面内原有的“切换模型”下拉框。
* **一次写入，终身接管**：当用户点击【一键接管】后，网关将该工具物理配置文件中的 `base_url` 改写为 AIGateway 的统一入口（如 `[http://127.0.0.1:18080/v1](http://127.0.0.1:18080/v1)`）。写入成功后，用户无需再改动此文件，工具的模型选择与分发完全由`[模型管理]`动态控制。


4. **环境快照安全沙箱**：写入前必须对用户原配置文件执行物理备份（`.bak` 快照队列）。卡片内必须提供【一键卸载/恢复初始】按钮，随时能将用户工具环境无损还原。



### 3.5 统一入口与实时计费模块 (Gateway & Billing) (需求 1, 7)

* **职责边界**：本地反向代理唯一关卡，承担全动态虚拟化路由。
* **功能需求**：
1. **虚拟平滑路由**：解析客户端传入请求的 `model` 字段（如 `model: "gpt-4o"`），在网关内存中与 SQLite 路由表匹配，映射给当前最健康的活跃厂家。
2. **双流（Dual-Stream）解析计费器**：
* 中间件必须支持对流式传输（SSE，`text/event-stream`）进行实时拦截并逐块（Chunk）解析。
* 当流式传输正常结束（收到 `[DONE]` 标记）时，实时累加计算本次请求消耗的 `prompt_tokens` 与 `completion_tokens`，并即时写入 SQLite 更新厂家余额。

## 4. 技术演进与工程约束 (面向 AI 开发者的 Checklist)

为确保 AI 辅助开发或编写 V2 代码时不偏离轨道，必须强制遵守以下底层约束：

### 4.1 数据库持久层规范 (SQLite Schema)

必须建立清晰的实体关联，严禁使用混乱的非结构化 JSON 承载状态。

* `providers` 表：记录厂家基础通路信息（预设类型、API Key、Base URL、数据格式标准）。
* `model_groups` 表：记录抽象出的虚拟模型组（如 `deepseek-v4-pro`）及全局切换策略配置。
* `provider_models` 表：**1 : N 关系表**，将单个厂家具体的模型节点（如 `provider_id: 1, model_id: "deepseek-chat"`）绑定到对应的 `model_group_id`。同时在此表维护该通道的可用状态、优先级、Token 计数及剩余额度。

### 4.2 统一的工具驱动接口 (Plugin Driver)

所有应用工具的接入必须实现统一的抽象接口（以 TypeScript 为例），严禁写死 `if-else`：

```typescript
interface ToolDriver {
   toolId: string;                              // e.g., "chatgpt", "claude_code", "openclaw", "harness"
   toolName: string;                            // UI 界面展示名称
   configType: 'toml' | 'json' | 'yaml' | 'env'; // 配置文件物理格式
   defaultPaths: string[];                      // 跨平台默认物理搜索路径
   
   detectConfig(): { path: string; status: 'found' | 'missing' };
   injectGateway(configPath: string, gatewayUrl: string, apiKey: string): boolean;
   rollback(configPath: string): boolean;       // 安全沙箱：一键回滚卸载，还原物理配置文件
}

```

### 4.3 容错返回规范

若网关内部发生 Failover 熔断且队列中所有备用厂家均告罄，网关必须向客户端返回 OpenAI 规范的标准错误 JSON，**严禁直接抛出标准 HTTP 500 导致下游开发工具闪退**：

```json
{
  "error": {
    "message": "AIGateway Error: All provider backups for this model group have been exhausted or rate-limited.",
    "type": "insufficient_quota",
    "param": "model_group",
    "code": "model_group_all_exhausted"
  }
}

```
